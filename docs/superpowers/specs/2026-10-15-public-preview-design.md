# MailTrans 0.10 public development preview

Implement install/onboarding, timeout/retry, automatic-translation pause, compatibility validation, update/uninstall, and CI/release improvements as a development preview without paid signing credentials. Developer ID signing, notarization, and physical testing on other Macs remain external prerequisites, not fabricated successes.

## Product behavior

Retain Apple Mail as the reader, Chinese target, original/attachment byte preservation, Chinese-original bypass, existing Mail remote-image policy, no telemetry/cloud translation, and menu bar daily use. Keep clear-cache first and no top status text row. Add a persistent checked automatic-English-translation toggle (default enabled), cancel-current-translation, retry-last-failed-message, and settings/help. Pause cancels automatic pending/current work but retains explicit manual translation and cached switching; cancelled or late responses cannot replace originals. Resume reconsiders eligible cached messages. Error indication uses the menu icon plus descriptive tooltip; retry is explicit, never an endless automatic loop.

Bound worker lifetime to 120 seconds; bound output to 8 MiB. Terminate the owned child on timeout/cancel, escalate to SIGKILL after 0.5 seconds if required, and drain I/O without blocking on a child that does not consume stdin. Never terminate an unrelated process. Clear, restore, pause of automatic work, and quit invalidate/cancel matching work. Advance the queue after failures/cancellation. Retrying an expired message gives an actionable reopen instruction; never retry a different email silently.

Provide a compact native AppKit setup/settings window on first launch and on demand. It remains usable with Mail closed, explains how to start Mail, checks extension registration with the system pluginkit tool and explicitly asks users to confirm the enable checkbox in Mail (the selected MailKit SDK exposes no enabled-state query), checks English→Chinese model availability, provides native language preparation, and reports automatic-launch status. Offer Mail opening, enabling instructions, language preparation, optional automatic lifecycle enable/disable, synthetic sample opening, release-page update link, help, and uninstall. No continuous polling or disruptive popups during automatic translation. Setup-state completion is explicit; first-run window does not reappear on every automatic launch.

Native per-user lifecycle management writes/loads/removes only the known MailTrans LaunchAgent, validates the actual installed app/signature, and reports errors. Uninstall requires a concrete native confirmation; removes the watcher before attempting to trash only this exact app, clears translation cache, unregisters its extension, and respects Mail's running state. Does not delete a parent directory, mailbox data, or Apple models. No dependency on system Python for app GUI operations. Update entry opens GitHub Releases; no unauthenticated auto-download or self-modifying updater.

## Implementation boundaries

Use existing Objective-C/AppKit/Swift/Python and stable bundle IDs/URL scheme. Add MTProcessRunner.h/.m + ProcessRunnerTests.m for bounded process execution; integrate host cancellation, preferences, menu/error state in ProbeApp.m/AppTests.m. Add MTSetupController.h/.m + MTAppManagement.h/.m + management/setup tests. Setup controller interface: initWithPreferences:(NSUserDefaults *)preferences; properties languagePreparationHandler(void(^)(void)), cacheClearHandler(void(^)(void)), quitHandler(void(^)(void)); methods showWindow, markSetupComplete; responds safely with Mail absent. Management API settled by its implementer and reported for integration. Host initiates English setup through its existing prepareLanguage:completion:; setup refreshes when brought forward. Use an overridable showSetup hook in app tests to avoid actual first-run windows.

Build 0.10 / build 10. Add CLI build options for selected DEVELOPER_DIR rather than hardcoding it; native-tests-only mode independent of newer Translation SDK, using the runner OS deployment target for test executables. App deployment floor remains 26.4; full app builds require SDK 26.5. GitHub CI must run meaningful Python and native regression checks on available hosted ARM macOS; full app build must either pass an explicit suitable toolchain check or report unsupported environment honestly. Native tests must not depend on real Mail contents or installed language models.

Create a clean development app ZIP, checksum, and release instructions documenting ad-hoc signature/no notarization. Package only the app (no work/cache/source messages). Tests verify archive contents, executable permissions, bundle integrity, and failure on wrong/incomplete inputs. Distribution script can accept an existing Developer ID identity/notary keychain profile later, without collecting credentials or weakening Gatekeeper. No paid services, certificates, or keys created automatically.

## Validation and delivery

Baseline full native build, focused fail-then-pass tests for runner/pause/setup-management/packaging, full integrated build/signature checks, installed worker verification if models available, synthetic-Mail UI walkthrough where possible, independent review, public branch/CI run, merge after verified checks, new v0.10.0 pre-release with explicit development-build warning. Keep v0.9.0 tag unchanged. Record hardware/OS/toolchain and actual coverage. Provide a small compatibility checklist others can execute; do not claim independent physical Macs were tested.
