# 苹果邮件本地翻译 · 试用版 0.6

现在使用苹果 Translation 框架进行真正的本地机器翻译，支持普通邮件，不再使用固定中文样本。已在这台 Mac 的苹果“邮件”中验证：英文 → 中文 → 恢复英文；表格、段落底色、内嵌图片和链接保留。英中语言包已经准备好。

## 现在怎样用

1. 程序已安装到 **应用程序 → Mail Translation Probe.app**。保持它运行；现在只在菜单栏显示翻译气泡图标，不再显示独立面板或 Dock 图标。不要再打开文稿目录中的构建副本。
2. 在苹果“邮件”中打开英文邮件，会自动在后台翻译成中文，无需先点翻译。第一次打开需短暂等待；已有缓存时直接显示中文。自动翻译不会弹出面板或切走阅读焦点。
3. 中文译文上方只显示 **显示原文**；点击它，切回原始邮件内容，同时保留控制条。控制条作为独立内容显示在邮件上方，原邮件的 HTML、编码和附件原字节保留；会沿用原邮件的外层样式，尽量保持排版。
4. 切回原文后，这封邮件在有效缓存期间保持原文，避免自动翻译立即覆盖选择。英文原文上方只显示 **翻译为中文**；点击它可再看中文。已有译文会直接切回，不重新翻译；没有译文时才调用本地翻译。

其他语言可通过正文上方的“翻译为中文”手动翻译。如果需要本地语言包，点击后按原生提示完成准备。取消或失败则保留原文，不会使用云端回退。

如果邮件没有及时自动刷新，可点菜单栏翻译气泡图标 → **重新加载当前邮件**，或关闭这封邮件的独立窗口后重新打开。小工具退出后自动翻译停止；重新打开小工具即可继续。

菜单栏图标的下拉菜单提供当前状态、**清空本地缓存**、**重新加载当前邮件**和**退出邮件翻译**。翻译遇到问题时可在这里查看状态。首次缺少语言包时，仍会按需显示苹果的语言准备窗口。

## 扩展开关

这台 Mac 的现有扩展已更新为 **邮件本地翻译**，在“邮件”→“设置”→“扩展”中启用。以后如果停用，需在这里重新勾选。

MailKit 会显示“读取所有邮件 / 修改发出邮件”的框架权限说明；本工具只实现阅读时的译文显示，不发送、转发或修改邮箱里的原邮件。工具不需要 AppleScript 自动化、辅助功能或全磁盘访问权限。

## 自己验证效果

直接用 Mail 打开本文件夹内的 `layout-sample.eml` 人工测试邮件。主题是 `Local translation acceptance - Thursday workshop`。

打开英文测试邮件后应自动看到“周四研讨会简报”、中文会议安排和原来的渐变图片；点击显示原文后应恢复 `Thursday workshop briefing`，顶部只保留“翻译为中文”，可继续切回中文。中文视图只保留“显示原文”。这是苹果模型生成的实际译文。

## 当前范围和限制

- 普通 HTML 和纯文本邮件；尽量保留结构、字体、底色、图片、表格与链接目标。文本变短或变长时，换行和自动列宽可能自然变化。
- 只翻译正文文字，主题和发件人等 Mail 标头保留原样；图片里的文字、附件正文、代码块不翻译。
- 暂时跳过端到端签名/加密邮件，以及过大或无法可靠解析的邮件。原始邮件上限 10 MB；单个文字节点上限 10,000 字符，整封翻译文字上限 200,000 字符。
- 英文邮件会自动排队，一次翻译一封。显示原文会取消该邮件排队或尚未完成的译文，避免迟到的结果覆盖原文。失败的自动任务不会因一次刷新反复重试；可手动重试。
- 苹果本地模型对很短的标题、表格单词或专业术语可能不够准确，例如单独的 `Status` 可能译得不理想。可随时对照原文。
- 中文和原文视图均沿用 Mail 现有的远程内容与隐私设置，插件不额外拦截联网图片，也不修改 Mail 的设置。内嵌 CID 图片保留；若 Mail 自身阻止远程内容，仍按 Mail 的加载提示操作。
- 这是本机临时签名的开发试用版，适配本机 macOS 26.4 和 Apple Silicon，尚未做分发公证或覆盖所有邮件格式。

## 本地缓存与停用

这里的缓存包括邮件原文临时副本（可能包含附件）、生成的中文阅读内容，以及这封邮件当前显示原文还是中文的状态，用来快速切换、避免重复翻译。它不是邮箱本身，也不是苹果翻译语言包。

这些内容只缓存在本机扩展容器 `~/Library/Containers/local.codex.mailtranslationprobe.extension/Data/Library/Caches/MailTranslation`，不会放入本项目的 Documents/iCloud 输出文件夹。缓存最多 20 封；30 分钟未使用则失效。工具运行时每分钟清理一次，正常退出时清空；若被系统强制结束，失效文件会在下次运行时清理。点击菜单栏翻译气泡图标 → **清空本地缓存** 可立即清除，原邮箱邮件和已下载的苹果语言包不受影响。再次打开或刷新邮件时，Mail 可能立即重新缓存当前原文；中文需要重新生成。

要停止试用：先清空本地缓存，再在 Mail 设置中取消勾选“邮件本地翻译”，退出小工具。Mail 自行保管的原文仍然存在。

## 预留其他翻译引擎接口

源码 `TranslationProvider.swift` 定义统一的 `TranslationProvider` 协议和 JSON 输入/输出。`TranslationWorker.swift` 通过 provider 名称注册引擎，目前只有 `apple-local`。宿主只传文字数组并接收相同顺序的译文；MIME/HTML 排版和恢复逻辑独立于引擎。

以后可增加其他 provider，在 worker 注册，并给菜单增加配置入口；不必重写邮件解析和显示。当前没有任何云端 API、密钥、网络翻译调用或自动回退。

开发验证：运行 `python3 source/build.py` 可重新编译并验证原生 MIME 测试和签名；运行 `python3 source/verify_worker.py` 检查实际本地翻译、结果顺序与错误路径。需要本机 Xcode。构建后将程序放在 /Applications 运行，避免在受 iCloud 管理的 Documents 内长期运行。

## 为什么它是一个 app

苹果 MailKit 采用“一个 macOS app 内包含 Mail 扩展”的结构。当前安装包中的 `.appex` 由 Mail 加载并处理邮件阅读内容；外面的 app 提供安装外壳，也负责运行本地翻译、缓存与模型准备。

程序只在菜单栏翻译气泡图标后台运行，没有独立翻译面板和 Dock 图标，你可以继续只使用苹果“邮件”收发和阅读。退出 app 会停止本工具的后台自动翻译。这个后台运行要求来自当前实现，并非所有 Mail 扩展都需要主程序持续运行。
