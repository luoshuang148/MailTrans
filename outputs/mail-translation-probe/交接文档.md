## 当前实现

这是一个包含 MailKit 扩展的 macOS app；app 外壳用于安装扩展，同时后台运行本地翻译和缓存管理。0.8 主 app 随 Mail 生命周期运行，另有无界面监听器在登录会话中待命。它没有独立阅读窗口。

- 宿主 ID：`local.codex.mailtranslationprobe`。
- 扩展 ID：`local.codex.mailtranslationprobe.extension`。
- 扩展包：`/Applications/MailTrans.app/Contents/PlugIns/MailTranslationProbe.appex`。
- 系统要求：目前只在本机 macOS 26.4 / Apple Silicon 验证，Mail 16.0，Xcode 26.6、macOS SDK 26.5。
- 安装为本机临时签名开发版，尚未公证或准备面向其他机器分发。
- Mail 设置 → 扩展 → **MailTrans** 已启用；运行使用 /Applications 中的安装副本。
- 0.7 应用图标原图及完整生成提示词在 `outputs/mail-translation-probe/assets`。构建脚本通过 `sips` / `iconutil` 打包 `AppIcon.icns`；菜单栏继续使用系统单色气泡图标。

| 源文件 | 职责 |
| --- | --- |
| `ProbeApp.m` | 菜单栏宿主；英文识别与自动队列；正文链接路由；缓存切换；worker 调用；Mail 刷新；语言包准备 |
| `ProbeExtension.m` | MailKit 阅读扩展；保存原始 MIME；返回当前阅读内容；通知宿主。0.6 中两个视图都返回 `shouldBlockRemoteContent:NO`，拦截原因是 nil |
| `MIMECore.h/.m` | MIME/编码/HTML 解析、可翻译文本选择、原文包装、译文生成、单操作控制条、缓存、请求失效控制、队列 |
| `TranslationProvider.swift` | 统一 TranslationProvider 协议与 JSON 输入输出数据结构 |
| `TranslationWorker.swift` | 苹果 Translation 框架实现及引擎注册，目前只有 `apple-local` |
| `LanguageSetup.swift` | 缺少语言包时按需显示原生语言准备 UI |
| `CoreTests.m` | MIME、编码、HTML、附件、状态隔离、缓存检查 |
| `AppTests.m` | 菜单、自动翻译策略、错误引导、缓存切换与清缓存取消任务 |
| `ExtensionTests.m` | 原文/中文控制条、源字节保留及两种视图不额外拦截远程图片 |
| `MailLifecycle.h/.m`、`LifecycleMain.m` | NSWorkspace.runningApplications KVO 观察、会话抑制、无焦点启动、正常退出及迟到启动清理 |

| `verify_worker.py` | 实际苹果本地翻译、批次顺序、中文保留及错误路径验证 |

处理链路：Mail 阅读扩展缓存邮件 → 通知宿主 → NaturalLanguage 判断英文并排队 → Swift worker 返回逐段中文 → 生成译文 MIME → 缓存 → 公开的 `MEExtensionManager reloadVisibleMessages` 刷新。

正文操作使用 `mailtranslationprobe://translate/<64位SHA256>` 和 `mailtranslationprobe://restore/<64位SHA256>`。严格校验消息键与 URL 形状，每封邮件独立状态。显示原文、清缓存会使未完成请求失效，防止迟到结果覆盖选择。缓存中文切换放在 busy 检查之前，因此另一封正在翻译时也能快速切换已存在的译文。

原文视图通过 multipart/mixed 在完整原始包前加入独立 HTML 控制部分。Mail 会合并多个 HTML 部分，控制部分需沿用原 body 的展示属性，避免丢失边距。中文视图只替换选中的可见文本；图片 URL、链接目标、样式和附件不作为文字送入翻译。

## 缓存的含义与生命周期

目录：`/Users/zongzihao/Library/Containers/local.codex.mailtranslationprobe.extension/Data/Library/Caches/MailTranslation`。

内容是邮件原文临时副本（可能含附件）、生成的译文及当前原文/中文选择，不是邮箱本身，也不是苹果语言包。不要把真实邮件缓存复制进项目交付、测试夹具或交接文档。

最多 20 封，距最近 Mail 读取登记 30 分钟后失效。运行时每分钟清理，正常退出清空；强制结束可能遗留文件，下一次运行清理。目录权限 0700、文件 0600，并校验键、源哈希和符号链接。清空不删邮箱邮件和语言包；刷新后当前原文可能立即被 Mail 重新缓存，中文需要重新生成。

## 构建与更新注意事项

在项目根目录运行：

```sh
/opt/homebrew/bin/python3 outputs/mail-translation-probe/source/build.py
/opt/homebrew/bin/python3 outputs/mail-translation-probe/source/verify_worker.py '/Applications/MailTrans.app/Contents/MacOS/TranslationWorker'
/usr/bin/codesign --verify --deep --strict '/Applications/MailTrans.app'
```

build.py 使用 `/Applications/Xcode.app/Contents/Developer`，会运行四组原生检查。已有测试二进制位于 `work/mail-real/core-tests`、`app-tests`、`extension-tests`；改源码后应重新编译，不能靠旧测试二进制证明修改通过。

**构建不会自动替换 /Applications 安装副本。** 更新的一般流程：

1. 更新前执行 `source/manage_lifecycle.py disable` 停用监听器，然后在 Mail 设置中暂停扩展；结束这个工具自身的旧宿主/扩展进程，避免覆盖正在使用的包。不要误结束其他程序。
2. 将新构建复制到 /Applications 的临时目录，保持五个可执行文件权限；先验证签名。
3. 用 pluginkit 移除旧安装包和 outputs 构建包的旧注册；保留旧 app 到 work 中不冲突的备份路径，替换正式安装包。
4. 验证正式包签名，注册正式 `.appex`，在 Mail 设置重新启用。权限身份不变，不增加新的系统访问能力。
5. 执行 `source/manage_lifecycle.py enable` 重新启用监听器；如果 Mail 正在运行，它会自动启动宿主。如 Mail 未加载新扩展，退出并重新打开 Mail；0.6 此次更新确实需要重启。
6. 确认实际进程路径，再在 Mail 检查中文/原文切换和图片。

Documents 受 iCloud FileProvider 管理，会反复为 .app/.appex 增加 FinderInfo 导致签名报错。build.py 仅清理生成包的 `com.apple.FinderInfo` 和 `com.apple.ResourceFork`，保留 quarantine/provenance 等其他属性。复制安装曾使用 `shutil.copytree(..., copy_function=shutil.copyfile)`，另设五个二进制的 0755 权限，避免复制不兼容元数据。不要从 Documents 长期运行构建副本。

若通过电脑界面操作，使用当前会话提供的电脑操作工具；先重新获取界面状态，不复用上一会话的元素索引。无窗口菜单栏 app 的绑定超时是工具限制，不能据此恢复用户不需要的面板。

## 已知限制与后续可观察点

- 苹果本地翻译偶尔首次失败，当前保留原文，可手动点正文按钮重试；尚无自动重试机制。
- 自动翻译只对识别为英文的正文排队，一次一封；其他语言手动。缺少模型时按需准备，当前英中模型已具备。
- 只翻译正文；主题、发件人、图片中文字、附件正文与代码块不翻译。短标题、单词和术语质量取决于苹果模型，中文长度变化也会影响自然换行。
- 原始邮件上限 10 MB，单文字节点上限 10,000 字符，整封翻译文字上限 200,000 字符。跳过签名/加密及无法可靠解析的邮件。
- 0.5 独立审查提醒：URL 冷启动可能早于 `applicationDidFinishLaunching` 初始化缓存/队列。目标 macOS 26.4 尚未复现失败；这是待观察项，不是已确认故障。
- 早期原生 MailKit banner/action 曾触发两次 ViewBridge 崩溃，因此现在使用 HTML 正文链接；不要未经验证改回该机制。
- 0.8 新增当前用户 LaunchAgent：`~/Library/LaunchAgents/local.codex.mailtranslationprobe.lifecycle.plist`。它让无界面监听器登录后待命，主应用仅在 Mail 运行时启动。停用/卸载前运行 `manage_lifecycle.py disable`。
- 当前没有其他引擎配置界面、正式签名、公证或跨机器测试。

最近功能要求：统一为 **MailTrans**，随 Mail 启动/退出，并尊重本次 Mail 会话中的手动退出选择。0.8 保留 bundle IDs、缓存位置、URL scheme、翻译与图片隐私策略。
