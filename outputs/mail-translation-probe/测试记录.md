# 本机验证记录 · 0.2

环境：macOS 26.4 / Apple Silicon / 苹果“邮件”16.0 / Xcode 26.6。

- 原生 MIME 检查：初始空实现出现 17 项预期失败；完成后通过。追加 UTF-8 主题及过期译文不能复活回归测试，先观察到两项失败，修正后全部通过。
- 编码与结构：纯文本、HTML、嵌套 multipart、alternative 的 HTML 选择、base64、quoted-printable、ISO-8859-1、LF/CRLF、附件原字节、CID 地址、HTML 链接和内联样式保留。
- 隔离与恢复：逐邮件 SHA-256 指纹、恢复原始源字节、多封状态互不影响、旧请求结果失效、缓存缺失/过期/非法键/符号链接拒绝、20 封限制、清空缓存通过。
- 保护类型：multipart/signed、PKCS#7 MIME、内联 PGP 跳过；脚本、样式、隐藏文字、代码块不送入翻译。
- 苹果翻译：通过原生界面下载英中本地语言包；新英文句子实际得到中文结果；多文本结果顺序、中文原样保留、未知 provider 不回退、非法输入返回结构化错误均通过。
- 应用：宿主、MailKit 扩展、本地翻译 worker、语言包 helper 编译通过；临时签名及 deep/strict 签名检查通过。
- Mail 实测：新版扩展启用；人工新邮件原文顶部出现两个控制链接；点击翻译后，正文在原位置显示“周四研讨会简报”等实际中文；表格、段落底色、渐变 CID 图片和链接目标保留；点击显示原文后恢复英文。此轮未发生 Mail 崩溃。
- 原文未写回邮箱。使用的是随附人工邮件，没有代替用户挑选或翻译私人真实邮件。

此前 MailKit 原生 banner/action 在这台机器触发 Mail ViewBridge 崩溃，已经避开，不使用该按钮机制。当前控制链接属于邮件阅读 HTML，小工具调用公开的 reloadVisibleMessages 刷新。

边界：没有覆盖所有真实邮件、图片内文字或附件翻译；签名/加密邮件跳过；短词翻译质量由苹果本地模型决定。真实邮件请由用户自行选择几封试用并反馈。

最终独立审查发现三项问题，均补充复现测试后修正：整个 multipart 附件子树保持原字节；独立 mixed 纯文本和 HTML 正文都参与翻译，related 只选择声明的根正文；同主题邮件在备用选择器中分别保留。新增 5 项 MIME 检查和 1 项原生 AppKit 场景，先失败后通过；最终完整构建、原生检查、本地实际翻译和签名检查通过。

运行副本已安装到 `/Applications/Mail Translation Probe.app`，避开 Documents/iCloud 反复附加 FinderInfo 导致的签名检查失败；安装副本的 deep/strict 签名检查和真实本地 worker 检查通过。宿主和扩展进程均确认从 /Applications 运行。
