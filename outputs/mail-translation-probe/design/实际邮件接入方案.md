# 早期邮件翻译接入方案

> 历史设计，仅供了解原型演进。旧面板、手动流程与模型准备状态不代表当前版本，现行行为见[项目首页](../../../README.zh-CN.md)和[架构说明](../../../docs/architecture.md)。

目标：继续使用苹果“邮件”，手动翻译几封真实邮件，在原正文位置显示中文，并能恢复原文；尽量保留标题、段落、图片、表格和链接。

## 第一版使用方式

1. 打开一封普通外文邮件。
2. 在正文上方的本工具阅读控制条点击“翻译为中文”，或从小工具选择最近打开的邮件并翻译。
3. 译文生成后由 Mail 重新显示这封邮件；操作时明确标出邮件主题，避免切换错邮件。
4. 使用“显示原文”恢复。原邮箱中的邮件不改动，不发送或转发邮件。

控制条属于我们返回的阅读内容，避开已经在本机复现崩溃的 MailKit 原生横幅按钮。菜单栏和小工具仍保留。

## 翻译引擎

第一版使用苹果本地 Translation 框架。自动识别主要语言，译为简体中文，不把正文交给云端翻译服务。英中语言模型已安装；日中、法中、德中等支持的语言组合首次需要下载相应语言包；下载的是模型，不是上传邮件。遇到不支持的语言或未完成的下载，保留原文并说明原因。

翻译 worker 使用统一 TranslationProvider 协议及 provider 注册表，宿主只交换有序文字数组。以后可接入其他翻译工具，排版处理无需重写。如果用户选择云端 API，需另行确定服务商、地址及密钥；不会静默切换到云端。

## 邮件和排版

- 支持普通 HTML 和纯文本邮件，处理 MIME 多部分结构、base64、quoted-printable 和常见字符集。
- 只翻译可见文字；不翻译 HTML/CSS 代码、链接地址、脚本、图片数据或附件。
- 保留图片附件原始字节，译文单独缓存。文字长度导致的自然换行、自动列宽变化允许发生。
- 第一版跳过端到端签名/加密邮件，避免改变验签和解密语义。
- 每封邮件按内容指纹单独存储状态；一封翻译不能改变另一封。

## 本地数据

扩展和宿主需要通过扩展自己的本地缓存交换邮件。缓存仅在这台 Mac 的应用容器中，最多保留近期20封、30分钟；提供清空缓存按钮。日志不记录邮件内容、地址或密钥。原邮件始终由 Mail 保管。

## 实现与验证步骤

1. 为 MIME、编码、HTML 文字节点和逐邮件缓存建立针对性测试，覆盖图片不变、链接不变和多邮件隔离。
2. 接入本地 Translation，先用无预设译文的人工邮件验证真实机器翻译与模型下载流程。
3. 升级现有扩展和小工具，加入逐邮件入口、错误提示、恢复原文和清空缓存。
4. 在 Mail 中验证真实翻译后的人工邮件和恢复原文，再交给用户亲自选择几封真实邮件测试。

本方案的成功标准是“真实翻译引擎 + 普通邮件处理 + 原位显示与恢复”，不再用固定中英文对应表冒充翻译效果。
